## Feedback pass — 10 September 2026

The user review of the first usable Prospection screen identified several semantic/UI gaps. The GPT branch now implements the corrections without widening V1 scope:

- legacy `Référent` marker `v` is treated as historical employment verification when no explicit verification column exists; `xxx` / `?` remain unverified and are never created as referents;
- a future Excel `Vérification` column is first-class; a verified row without a source date receives the import timestamp automatically;
- `S37`, `S39`, etc. become a real planned-contact date on the Monday of the nearest ISO week around import time, including year-boundary continuity;
- clean legacy referent names, phone/mobile, address, activity category and company project/reference context are imported instead of being dropped;
- re-import merges useful information into an existing prospect while preserving durable `do_not_contact` and not downgrading an existing verified record from an empty/unverified import;
- the prospect drawer separates database maintenance from contact follow-up using tabs;
- employment verification dates, email verification dates, response dates and stage-change dates are generated by VIPER rather than manually typed;
- tracking labels are French and user-facing labels never expose snake_case/camelCase identifiers;
- the people list prioritizes identity, verification quality and contact stage, adds quick filters, and remains horizontally scrollable when extra information does not fit.
